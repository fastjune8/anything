## 위험과 주의

- **병합과 충돌:** 시각 메쉬를 병합해도 충돌 박스는 `shared/maps/build.js`가 따로 만든다. 병합은 `client/js/world.js` 쪽에서만 한다.
- **서버·클라이언트 공유:** `shared/maps/`는 서버도 쓴다. 장식용 데이터를 추가해도 서버 검사(`checkMap`)가 통과해야 한다.
- **장식과 시야:** 충돌 없는 장식은 총알을 막지 않는다 (Bible 9.3). 큰 장식은 만들지 않는다.
- **측정 전 확정 금지:** 성능 상한(Bible 10.1)은 임시값이다.
- **범위 밖:** 캐릭터·총기·옷 규격, 게임플레이, 레이아웃, 라이브 배포.


## 3차 작업 결과 (P1-5) 와 다음 우선순위

- 완료: 정적 박스·나무 병합 (분석 9장). 충돌·총알·그림자 설정·스폰·거점은 변경 없음.
- **새로 확인한 병목:** 이제 한 프레임의 삼각형 약 90%(약 186k/약 410k 중)는 캐릭터 `SkinnedMesh`이고, draw call은 캐릭터 부품 약 213개 ×(메인+그림자)가 큰 몫이다. 맵 디테일을 더하기 전에 캐릭터 비용을 확인해야 한다 (별도 과제로 기록만 함, 이번 범위 밖).
- 다음: ① P1-6 그림자 비용 (정적 맵 그림자 베이크·해상도·품질 단계) ② 캐릭터 draw call 분석 ③ 먼 산·이펙트 풀 정리 ④ P1-2·P1-3·P1-4·P1-7 (병합이 있으므로 장식 박스 추가의 draw call 부담이 작아짐 — 단, 장식은 같은 재질 키를 써야 병합됨).
- 병합 칸 크기(`MERGE_CELL`=40m)는 조정 가능. 더 큰 칸(60m)도 시험했으나 봇 오차 때문에 실측으로 우열을 가리지 못해 40m 유지.
- 아직 미측정: 실제 GPU FPS, 1920×1080, 병합이 그림자 패스 draw call에 미친 정확한 크기.

### 단계별 작업 설계

**P2-1 핵심 환경 오브젝트 개선** (이 단계는 색·실루엣 중심, 가장 먼저)
- 색 (P0 3건): `shared/maps/parts.js`(`barrel` 기본 tint), `content/looks.json`(`concreteDark`·`metal`·`wood`·`ground` 색), `tools/maps/gen_outpost.mjs`(컨테이너 틴트), `tests/envcolor.test.mjs`(레이아웃 결과 기준 검사로 확장). 주의: `looks.json`의 `sunlit`은 다른 맵(`frontline`·`warehouse`·`test`)과 공유한다.
- 실루엣: `parts.js`의 `container`·`barrier`·`sandbags`·`barrel`에 `noCollide` 장식 박스 추가. 충돌(`colliders`)은 원래 박스 그대로이므로 서버·예측에는 영향이 없다 (서버가 같은 `parts.js`를 쓰므로 장식은 반드시 `noCollide`).
- 대상: 방벽 14, 컨테이너 13, 드럼통 8, 모래주머니 7, 상자 21(필요 시).
- 검증: `npm test`, 가드 테스트, 12곳 전후 캡처, 측정(분석 8·9장 절차).

**P2-2 건축물 구조 개선**
- 파일: `shared/maps/parts.js`(`wallRun`·`building`), `tools/maps/gen_outpost.mjs`.
- 대상: 건물 1(창고), 벽 14(벽돌 8 + 콘크리트 등), 문 22·창 13, 외곽 벽 4, 스폰 벽 2, 플랫폼 B, 감시탑, 계단 2.
- 규칙: 틀·기단은 기존 벽 재질 키를 재사용(병합 유지). 틀 깊이 0.12~0.15m, 충돌 없음. 길이 40m 이하로 분할. 문턱·틀이 이동·시야를 가리지 않도록 문 폭은 그대로.

**P2-3 재질 및 텍스처 개선**
- 파일: `client/js/world.js`(`getMat`, `STYLE`, `drawMat`), `content/looks.json`.
- 내용: 높이 전용 캔버스(`bumpMap`) 분리, 필요하면 roughness 캔버스, 콘크리트 얼룩 제거, 지면 이중 스케일, `sandbag`을 `classic`에서 `sunlit` 스타일로.
- 제약: 새 이미지 에셋 없음(절차 생성). 맵·룩 전환(`setLook`) 때마다 재생성되므로 **로드 시간 측정 필요**. 스튜디오 룩 에디터에서 재질 편집 시 새 캔버스도 갱신되어야 한다.

**P2-4 조명·원경·분위기 개선**
- 파일: `content/looks.json`(`fill`, `fog`, `hills`, `exposure`), `client/js/world.js`(산 2단, 환경 반사), 필요하면 `scene.js`.
- 내용: 그림자색, 산·안개 깊이, 지면 먼 곳, 금속 반사. 각 변경은 가독성 캡처(아군/적을 세운 상태)로 확인한다.

**P2-5 추가된 에셋의 성능 최적화**
- 매 단계 후 측정: draw call·삼각형·지오메트리(분석 8·9·10장 절차 그대로).
- 예산(제안): 맵 메쉬 ≤ 140, 맵 삼각형 ≤ 20k, 새 (재질, tint) 키 ≤ 2개. 초과하면 병합 키·칸 크기를 조정한다.
- 가드 추가 검토: 새 재질 키 수와 맵 메쉬 수를 세는 자동 검사(작게).
- 별도 과제(환경 아님): 캐릭터 메인 패스 `frustumCulled=false`(분석 10.6).

### 새 장식의 가독성 규칙 (Bible 9.3·12장과 함께 적용)

1. 충돌 없는 장식은 **두께 0.15m 이하·돌출 0.15m 이하**로 시야·총알 통과 기대와 어긋나지 않게 한다 (총알은 충돌 박스만 보므로 장식이 시각적으로 막아도 총알은 통과한다 → 장식이 엄폐물처럼 보이면 안 됨).
2. 청·빨강 색조를 쓰지 않는다 (가드 테스트가 막음).
3. 엄폐물(상자·방벽·컨테이너·모래주머니)의 외곽 크기는 바꾸지 않는다.
4. 팀 색 옷을 입은 캐릭터 앞에서 캡처해 확인한다 (이번 진단에서는 옷이 적용되지 않아 확인하지 못함).
