# 게임 엔진 (v3)

> 기준 문서: [`GAME_DESIGN.md`](GAME_DESIGN.md). 이 문서는 그것을 코드로 옮긴 방식과, 기획서에서 **미확정**이라 임시로 정한 값을 적는다.

## 한 줄 요약
**서버 권한 · 60Hz 고정 시뮬레이션 · 같은 코드로 브라우저 예측 · 스냅샷 보간 · 되감기 판정** (오버워치·CS 와 같은 구조).
이동·사격·스킬이 전부 `shared/sim/` 의 결정적 함수 하나(`stepPlayer`)로 돌아가고, 서버와 브라우저와 봇이 그 함수를 같이 쓴다.

```
브라우저                                         서버 (방 하나, 60Hz)
 키·마우스 → cmd(1/60초)                          
   ├ stepPlayer → 바로 반응 (예측)                 cmd 도착 → stepPlayer (같은 함수, 권한)
   └ cmd + vt(화면에 보이던 서버 시각) ───────────▶   ├ 사격 사건 → 다른 사람을 vt 로 되감아 히트스캔
                                                     ├ 피해 → 처치 → 자동 부활 / 점수 / 승패
 me(내 상태) ◀──────────────────────────── 30Hz ──┤ 봇: brain.js 가 같은 cmd 를 만든다
   └ 서버 상태로 맞추고 남은 cmd 를 다시 계산(보정)  └ 스냅샷(다른 사람) · 사건 묶음
 snap ◀─────────────────────────────────── 30Hz
   └ 0.1초 뒤를 두 스냅샷 사이로 보간해 그림
```

## 파일

| `server/game/modes/` | 점령전 · 데스매치 규칙 |
| `server/bots/brain.js` | 봇: 시야·반응 시간·조준 오차·거리 유지·무빙·점프·슬라이딩·무기 교체·스킬·길찾기 |
| `server/lobby/` | 계정(레벨·전적)·친구·파티·채팅·빠른 매칭·커스텀 방 |
| `client/js/predict.js` | 예측 · 보정(어긋남은 화면에서 부드럽게) · 사격 연출(반동·궤적·맞힘 표시) |
| `client/js/clock.js` | 서버 시각 추정 · 보간 시각 |
| `client/js/remotes.js` | 스냅샷 보간 · 다른 사람 모델·상태 연출 |

## 결정적 시뮬레이션 지키기
- `shared/sim/` 안에서는 `Math.random()`·`Date.now()`·`performance.now()` 를 쓰지 않는다 (난수는 `rng.js`, 시간은 dt).
- 상태는 순수 객체(`ps`)에만 둔다. 서버는 `me` 로 `ps` 를 통째로 보내고, 브라우저는 `copySim` 으로 받는다 → 새 필드를 추가하면 `copySim` 에도.
- 서버만 아는 일(피해·넉백 적용·투사체·출혈·스텔스 근접 해제)은 서버가 `ps` 를 바꾸고 `meDirty` 로 알린다 → 브라우저는 보정으로 따라간다.
- 확인: `tests/engine.test.mjs` 의 "결정성", 브라우저 테스트의 "최대 어긋남".
