# FRONTIER Studio

게임 콘텐츠(맵, 총 모델, 무기·파츠·모드 수치)를 만들고 고치는 도구. Unity 에디터와 비슷한 틀이다.
**각자 자기 컴퓨터에서 켜서 쓰고, 결과(content/ 의 파일)는 git 으로 주고받는다.** 같은 화면을 동시에 고치는 기능은 없다.

## 처음 한 번 (설치)

1. **Node.js 22 이상** 설치: https://nodejs.org (LTS)
2. **저장소 받기**
   ```bash
   git clone https://github.com/fastjune8/anything.git
   cd anything/games/frontline
   npm install
   ```
3. Chrome (또는 Edge) 최신 버전

## 매번

```bash
cd anything            # 저장소 맨 위에서도, games/frontline 에서도 된다
git pull               # 다른 사람이 올린 것 받기
npm run dev            # 개발 서버 시작
```
→ 브라우저에서 **http://localhost:3002/studio/** (게임은 http://localhost:3002)

끝나면 터미널에서 Ctrl+C.

## 화면

**처음 켜면 1분짜리 튜토리얼**이 화면 구성을 짚어 줍니다 (건너뛰기 가능, 도움말에서 다시 보기).

```
┌ ⌂ 홈 │ ▦ 창고 │ ✦ 무기 ●│ …탭 ───────────────────────── 모두 저장 · ? 도움말 ┐
│                                                                                │
│  홈:   [종류]       [카드 목록]                    [자세히]                       │
│        맵 · 모델     카드 한 번 = 자세히             미리보기 · 정보                  │
│        무기 · 파츠    카드 두 번 = 편집기로 열기       연결된 데이터 · 편집기로 열기      │
│        모드 · 효과                                                               │
│                                                                                │
│  편집기: [편집기 이름 · 고치는 것 · 버튼(되돌리기 · 보기 · 저장 · ▶ 플레이)]          │
│          [도구 상자]  [화면]                          [속성: 고른 것의 수치]          │
├────────────────────────────────────────────────────────────────────────────────┤
│ 콘솔 · 마지막 기록 (저장·오류)                                                     │
└────────────────────────────────────────────────────────────────────────────────┘
```
- **홈**: 게임의 모든 데이터를 종류별로 봅니다. 카드를 누르면 오른쪽에 미리보기·정보·연결(예: 이 맵을 쓰는 모드, 이 무기에 달 수 있는 파츠)이 나오고, **두 번 누르면** 맞는 편집기가 열립니다.
- **편집기**: 데이터 종류마다 따로 있습니다 — **맵 에디터**, **모델 에디터**(총, 물체는 준비 중), **데이터 에디터**(무기·파츠·모드), **효과 에디터**(준비 중). 모두 같은 모양(위 버튼 / 도구 상자 / 화면 / 속성)입니다.
- 탭의 **●** = 저장 안 됨. 위쪽 "저장 안 됨 N" 은 열린 것 중 저장 안 한 개수.
- **? (F1)**: 지금 편집기의 사용법과 단축키. 모든 조작법은 여기 있습니다.

| 단축키 | |
|---|---|
| ⌘S / Ctrl+S | 지금 탭 저장 (⌘⇧S 모두 저장) |
| ⌘Z / ⌘⇧Z | 되돌리기 / 다시 하기 |
| ⌘P | 시험 플레이 / 멈춤 (맵 에디터) |
| ⌘W | 탭 닫기 |
| F1 또는 ? | 도움말 |

## 맵

- **물체 놓기**: 왼쪽 도구 상자(구조물·엄폐물·자연·스폰·모드)에서 고르고 바닥 클릭 (Shift+클릭 = 계속 놓기)
- **고르기·옮기기**: 클릭, 끌기, 방향키(격자 한 칸). 오른쪽에서 수치 입력. 격자는 위쪽 메뉴 / G
- **카메라**: WASD 이동, Q/E 돌기, 오른쪽 버튼 누른 채 비행, Alt+왼쪽 끌기 궤도, F 선택한 곳, Home 전체
- **반대편에도 배치**: 맵 중심 대칭으로 하나 더 (양 팀이 공평한 맵)
- **▶ 플레이 (⌘P)**: 저장하지 않아도 **지금 모습 그대로** 화면 안에서 게임이 열린다. 모드·봇·"여기서 시작"(보고 있던 곳에서 태어남)을 고를 수 있다. ■ 또는 ⌘P 로 멈춤.
- 오류(맵 밖 스폰 등)가 있으면 화면 왼쪽 아래에 나오고 저장·플레이가 잠긴다.
- 저장하면 `content/maps/<id>.json`. 홈 → 맵 → **+ 새 맵** 으로 새로 만든다.

## 총 모델

Blender 로 만드는 규칙은 [GUN_MODELING.md](GUN_MODELING.md).
- 홈 → 모델 → **.glb 열기** (또는 화면 아무 곳에 끌어다 놓기) → 모델 에디터 오른쪽에 **규칙 검사** (✕ 는 꼭 고친다)
- 보기: 살펴보기 / 1인칭 / 정조준 (빨간 점에 가늠쇠가 겹치면 정상)
- 크기 비교, 파츠 달아 보기, 스킨(색 칸) 바꿔 보기
- 위쪽에 총 id 를 넣고 **프로젝트에 저장** → `content/guns/<id>.glb`
- **예시 모델** = 규칙대로 만든 예시
- **데이터로 등록**: 저장한 모델이 검사를 통과하면 등록하고 쓸 무기를 고른다 → **게임이 자동으로 그 모델로 총을 그린다** (1인칭·다른 플레이어·무기고 벽). 홈 카드에 등록됨 / 작업 중 표시

## 게임 데이터 (무기 · 파츠 · 모드)

- **새로 만들기**: 홈의 각 종류 위쪽 **+ 새 무기 / + 새 파츠 / + 새 모드** (모델은 **+ 새 모델 (.glb)**, 맵은 **+ 새 맵**). 양식의 * 칸을 모두 올바르게 채워야 만들어지고, 기준 항목의 수치에서 시작한다. 새 무기는 등록된 모델을 꼭 골라야 한다.
- **무기**: 표에서 고르고 오른쪽에서 수치를 고친다. **모델** 칸에서 등록된 모델을 고른다. 가운데 표가 DPS, 거리별 TTK(체력 100 을 깎는 시간)를 바로 다시 계산해 보여 준다. 밸런스 조정용.
- **파츠**: 자리(조준경·총열 …)와 파츠를 고르면, 달 수 있는 무기마다 좋아지는 점·나빠지는 점이 보인다. 추가·삭제 가능.
- **모드**: 인원, 봇, 목표 점수, 점령전 수치(점령 시간 등). 점수·승리 규칙 자체는 코드(`server/modes/`).
- 저장하면 개발 서버가 다시 시작되어 바로 게임에 반영된다 (열려 있던 게임은 다시 접속).

## 주고받기 (git)

스튜디오에서 저장한 것은 `content/` 의 파일이다. 코드와 같은 방법으로 올린다.
```bash
git pull                                  # 먼저 최신으로
git checkout -b map/canal                 # 작업 이름으로 브랜치
git add content/ && git commit -m "운하 맵 1차"
git push -u origin map/canal              # GitHub 에서 PR → 자동 테스트 통과 → 합치기
```
- 맵·데이터 파일은 **한 줄 = 물체/항목 하나**라서, 두 사람이 같은 맵의 다른 부분을 고쳐도 대부분 자동으로 합쳐진다.
- 같은 줄을 둘 다 고쳤으면 충돌이 난다. 그때는 한 사람 것을 고르고 스튜디오에서 다시 고친다.
- Blender 원본(.blend)은 저장소에 넣지 않는다 (용량). 게임에는 .glb 만.

## 라이브와의 관계

- 스튜디오는 **개발 서버에서만** 열린다. 라이브 서버에는 없다 (배포 파일에서도 빠진다).
- 스튜디오에서 저장한 내용은 `main` 에 합쳐진 뒤 **라이브 배포**를 해야 유저에게 보인다.
