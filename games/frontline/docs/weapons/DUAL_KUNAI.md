# DUAL KUNAI — Thread Manipulator (듀얼 쿠나이)

> 이 문서 = 기획 원문(아래 "기획 원문") + 실제 구현과 정한 값(바로 아래 "구현"). 수치는 플레이 테스트 시작점이다.
> 코드: `shared/sim/kunai.js`(공용·결정적) · `server/game/room.js`(직접 명중·와이어 감지·끊기·돌진 공격) · `client/js/kunai.js`(그리기) · 테스트 `tests/kunai.test.mjs`

## 구현 (2026-11-23, W1~W6 + W7 의 직접 명중)

### 조작 (기존 키와 겹치지 않게)
| 입력 | 기능 |
|---|---|
| 좌클릭 | 왼손 쿠나이: 준비면 던지기, 날아가거나 박혀 있으면 회수 |
| 우클릭 (또는 T) | 오른손 쿠나이: 같은 동작 (쿠나이를 든 동안 정조준 없음) |
| R | 둘 다 회수 (쿠나이는 재장전이 없다) |
| X | 기동 모드 ↔ 설치 모드 (새 키, 다른 데 안 쓰임) |
| F | 핀 노드: 조준한 벽·바닥(35m 안)에 와이어용 점을 박는다 (W9, 충전식 2개) |
| 무기 스킬 키 | 모드 능력 — **쿠나이가 1번 자리면 Q, 2번 자리면 E** (기획 원문의 E 는 기존 "자리별 스킬 키" 규칙에 맞췄다) |

- 쿠나이는 무기(9번째, `kind: "kunai"`)이고 모드 능력은 그 무기의 스킬 "실 조종"(`thread`, effect `kunai`)이다. 다른 무기를 들고 스킬 키를 누르면 쿠나이로 바꾼 뒤 발동한다.
- 던진 쿠나이·앵커·와이어는 무기를 바꿔도 남는다. 던지기·회수·모드 전환은 쿠나이를 들고 있을 때만.

### 직접 명중 (W7 에서 앞당김 — 제트 궁 감각, 조금 약하게)
- 조준선 그대로 날아가는 빠른 투사체 (62 m/s, 아주 약한 중력 3 m/s², 탄퍼짐 없음). 눈 위치에서 나가고, 화면에는 손에서 나가는 것처럼 그린다.
- 피해: 몸 45 · 머리 110 · 다리 36 (체력 150, 거리 감쇠 없음).
- 처치하면 그 쿠나이가 **바로 손으로** (이어 던지기). 처치하지 못하면 맞은 자리에서 돌아온다.
- 판정은 서버: 매 tick 의 비행 구간을 던진 사람이 보던 순간으로 되감은 적 자세(기존 랙 보정)로 검사한다.

### 앵커 (W1·W5)
- 벽·바닥·지붕 등 충돌 박스에 닿으면 그 자리에 박힌다. 허공 35m 까지 아무것도 없으면 돌아온다.
- 상태: 준비 → 비행 → 고정 → 회수 → (0.12초) → 준비. 손마다 따로.
- 고정 20초, 또는 플레이어가 35m 보다 멀어지면 스스로 회수.

### 기동 모드 (W2)
- 앵커 1개 → 그 앵커 앞(벽이면 손이 닿는 높이)으로, 2개 → 두 앵커의 가운데로 끌려간다. 순간이동 아님.
- 오버워치 위도우메이커 그래플 감각 (그래플 스킬과 같은 줄 이동, `shared/sim/movement.js`): 누르는 순간 최고 속도의 60%(약 17 m/s)로 바로 출발 → 최고 28 m/s 까지 곧게, 중력 12%, 최대 1.8초.
- 박힌 곳 위 2.2m 안에 올라설 윗면이 있으면 끝에서 **턱을 넘겨** 그 위에 올려놓는다.
- WASD 로 궤적을 틀고(옆으로 7 m/s), 점프하면 놓고 위로 튀어 오른다(앞으로 가던 속도는 그대로). 벽 목표는 다 와 가면 살짝 늦추고, 두 앵커 가운데는 속도를 그대로 가지고 지나간다(새총) → 착지 슬라이딩 등 기존 이동으로 이어진다.
- 줄 이동 중에는 위아래 속도도 속도감(시야각)에 들어간다.
- 기동 중 한쪽을 회수하면 남은 앵커로, 새로 박으면 두 앵커 가운데로 목표가 바뀐다. 넉백을 맞으면 끊긴다.

### 설치 모드 · 와이어 (W3·W4·W5)
- 앵커 2개가 모두 박혀 있을 때 스킬 키 → 두 앵커 사이 직선 와이어 8초 (앵커 수명과 따로).
- 적의 몸이 와이어 0.55m 안에 들어오면: 설치자에게 알림 + 미니맵에 그 위치 3초 표시, 적은 1.2초 동안 이동 속도 60%. 같은 적은 2.5초에 한 번. 피해 없음, 묶지 않음.
- 와이어는 모두에게 보인다 (내 편 하늘색, 적 주황). 총알·칼이 지나가면 끊긴다 (0.15m).
- 앵커가 하나라도 빠지면 와이어도 없어진다. 와이어가 먼저 사라져도 앵커는 남아 기동에 쓸 수 있다.
- 모드를 바꿔도 앵커·와이어는 그대로다.

### W9 와이어 네트워크 (`shared/sim/thread.js`)
- **노드** = 와이어를 걸 수 있는 점: 0 왼손 쿠나이 앵커 · 1 오른손 쿠나이 앵커 · 2·3 핀 노드. 최대 4개. 노드마다 세대 번호가 있어 빠졌다 다시 박혀도 예전 선분이 새 노드를 가리키지 않는다.
- **핀 노드 (F)**: 쿠나이를 든 동안 조준한 곳에 박는다. 충전 2개(하나 쓰면 12초 뒤 다시 하나), 20초 유지, 둘 다 박혀 있으면 오래된 것을 옮긴다. 기동(끌려가기)에는 쓰지 않는다 — 쿠나이 앵커만.
- **설치 모드 스킬 키** = 지금 노드들로 네트워크를 새로 만든다 (있던 것은 바꿔 놓는다), 노드를 박은 순서대로:
  - 2개 → 직선 와이어 (가로·세로·대각·기울기 모두 실제 두 점 그대로)
  - 3개 → 삼각 영역 · 4개 → 사각(다각형) 영역. 박은 순서로 이으면 꼬이면 둘레 순서로 다시 잇는다
  - 4개인데 첫 두 노드 선과 뒤 두 노드 선이 (위에서 볼 때) 엇갈리면 → 교차 와이어 2개 (교차점은 연결이 아니고, 판정은 선분마다 따로)
- **설치 검사**: 선분 길이 1~30m, 노드 사이를 벽이 막으면 안 됨, 영역 넓이(위에서 본) 4~450m². 안 되면 이유를 보여 주고 쿨타임을 쓰지 않는다. HUD 가 지금 노드로 무엇이 만들어질지(또는 왜 안 되는지) 미리 보여 준다.
- **수명·정리**: 앵커 20초 · 핀 20초 · 선분 8초(선분마다) · 영역 8초. 노드가 빠지면(회수·만료·사망) 그 노드에 걸린 선분만 빠지고, 영역은 변이 하나라도 빠지면 풀린다 (남은 선분은 그대로). 무기를 바꿔도 남고, 죽으면 모두 정리.
- **영역 감지 (서버)**: 적이 영역(위에서 본 다각형, 노드 높이 −1.5 ~ +2.5m) 안에 들어오면 설치자에게 알림 + 위치 2.5초 표시, 나가면 나갔다고 알린다. 안에 있는 동안은 다시 알리지 않고, 같은 적의 들어옴 알림은 3초에 한 번. 효과는 정보뿐 (감속은 `THREAD.area.slow` 로 켤 수 있게만 두었다, 기본 0).
- **와이어 감지·끊기**: 선분마다 기존과 같다 (닿으면 알림·느려짐, 총알·칼이 닿은 선분만 끊김). 판정 거리는 그림 두께와 상관없다 (감지 0.55m, 끊기 0.15m).
- **보이는 것**: 와이어는 모두에게 (같은 편 하늘색, 적 주황), 핀 노드는 빛나는 고리, 영역 바닥의 옅은 면은 같은 편만.
- **동기화**: 노드·선분·영역은 플레이어 시뮬레이션 상태(`ps.pins`, `ps.wires`, `ps.area`)라 브라우저가 예측하고 서버가 같은 계산으로 확정한다. 다른 사람에게는 바뀔 때만 `ku` 사건(`pn` 핀, `w` 선분, `ar` 영역). 영역 사건: `aenter`(위치) · `aexit`.

### 기동 공격 (W6)
- 끌려가는 중 9 m/s 이상으로 적과 부딪히면: 피해 35 + 진행 방향으로 밀어냄(7 m/s) + 0.25초 경직, 기동은 거기서 끝 (속도 35% 남김). 서버 판정, 한 번의 기동에 한 번.

### 네트워크
- 쿠나이 상태(손마다 상태·위치·속도, 모드, 와이어 남은 시간)는 플레이어 시뮬레이션 상태(`ps.ku`, `ps.kmode`, `ps.wire`)에 있어 브라우저가 예측하고 서버가 같은 계산으로 확정한다.
- 다른 사람에게는 상태가 바뀔 때만 `ku` 사건을 보낸다 (비행은 시작점·속도로 이어 그린다). 새로 들어온 사람에게는 현재 상태를 한 번 보낸다.
- 사건: `kuh`(사람에 박힘) · `wtrip`(설치자에게, 위치) · `wslow`(걸린 사람에게) · `wfx`(와이어 울림) · `wcut`(끊김) · `kdash`(기동 공격).

### 아직 안 한 것 / 알려진 한계
- 3인칭 던지기 동작은 따로 없다 (손에 든 쿠나이 하나 + 줄·날아가는 쿠나이만 보인다).
- 봇은 쿠나이를 고르지 않는다 (봇 출전 조합에 없음). 와이어에는 걸린다.
- 적 표식(W7 직접 명중의 위치 감지·끌어당기기), 오브젝트 상호작용은 아직.
- W9 에서 안 한 것: 영역 효과(감속·이동 방향 추적 — 켜는 자리만), 핀 노드 파괴, 와이어 장력 물리, 설치 애니메이션(선이 바로 생긴다).
- 수치는 시작점: `shared/sim/kunai.js` 의 `KUNAI` 한 곳에서 바꾼다 (피해는 `content/weapons.json`).

## 기획 원문

# DUAL KUNAI — Thread Manipulator
## 무기 기획 및 개발 통합 프롬프트

당신은 Three.js 기반 멀티플레이어 FPS 게임의 무기 시스템과 전투 메커니즘을 설계·구현하는 시니어 게임플레이 프로그래머입니다.

기존 게임에 새로운 특수 무기인 **Dual Kunai — Thread Manipulator**를 추가하려고 합니다.

이 무기는 양손에 장착된 쿠나이 두 개와 각각의 손목에 연결된 와이어를 이용하여 적을 공격하고, 전장에 앵커를 설치하고, 와이어를 연결해 공간을 통제하며, 와이어를 이용해 빠르게 이동하는 특수 무기입니다.

단순한 투척 무기나 일반적인 그래플링 훅이 아닙니다. 공격·기동·공간 통제라는 세 가지 기능이 하나의 무기 시스템 안에서 유기적으로 작동해야 합니다.

# 1. 핵심 무기 콘셉트

### 무기명
DUAL KUNAI — Thread Manipulator

### 전투 정체성
- Mobility: 와이어 앵커를 활용한 고속 기동과 경로 변경
- Control: 와이어를 설치하여 적의 이동 경로를 제한하고 감지
- Combat: 쿠나이 투척 및 기동 중 적과 충돌하는 공격

### 핵심 플레이 스타일

1. 전투 중 쿠나이 두 개를 서로 다른 위치에 설치한다.
2. 두 앵커를 연결하여 와이어를 설치한다.
3. 적이 와이어에 접근하거나 통과하면 위치를 감지하고 이동을 방해한다.
4. 설치한 앵커를 이용해 빠르게 이동하고, 적의 측면이나 후방으로 진입한다.
5. 전투 상황에 따라 기동 모드와 와이어 설치 모드를 전환한다.

이 무기는 돌격소총이나 저격총처럼 정면 교전에서 압도적인 화력을 제공하지 않는다. 대신 전장에 미리 만들어 둔 이동 경로와 와이어 네트워크를 활용하여 유리한 위치를 확보하는 데 강점을 가져야 한다.

# 2. 기본 무기 구조

플레이어는 왼손과 오른손에 각각 하나의 쿠나이를 장착한다.

각 쿠나이는 독립적인 상태를 가지며, 서로 다른 위치에 발사할 수 있어야 한다.

### 기본 조작

| 입력 | 기능 |
|---|---|
| 좌클릭(LMB) | 왼손 쿠나이 발사 / 설치된 왼손 쿠나이 회수 |
| 우클릭(RMB) | 오른손 쿠나이 발사 / 설치된 오른손 쿠나이 회수 |
| 모드 전환 키 | Mobility Mode / Thread Mode 전환 |
| E | 현재 모드에 해당하는 특수 능력 실행 |
| R | 양쪽 쿠나이 전체 회수 (초기 제안) |

※ 실제 키 바인딩은 반드시 기존 게임의 입력 시스템을 확인하고 충돌하지 않는 키를 사용합니다. 위의 조작은 기능적 기준이며, 기존 키 설정을 무조건 덮어쓰지 않습니다.

### 중요한 조작 원칙

- 좌우 쿠나이는 독립적으로 작동해야 합니다.
- 한쪽 쿠나이가 설치되어 있어도 다른 쪽 쿠나이를 발사할 수 있어야 합니다.
- 좌우 쿠나이의 발사 및 회수 조작은 두 모드에서 동일하게 유지합니다.
- 모드 전환은 E의 기능만 변경합니다.
- 모드를 전환하더라도 기존에 설치한 앵커와 와이어는 유지되어야 합니다.
- 플레이어가 직접 앵커를 회수하거나 제한 시간이 만료되면 해당 앵커가 제거됩니다.

# 3. 쿠나이 및 앵커 시스템

각 쿠나이는 발사 후 유효한 표면에 충돌하면 앵커로 고정됩니다.

### 앵커 설치 대상

초기 버전에서 허용할 대상:

- 벽
- 바닥
- 지형
- 건축물
- 충돌 판정이 존재하는 환경 오브젝트

유효하지 않은 대상:

- 허공
- 설치 불가능한 영역
- 게임 규칙상 앵커 설치를 허용하지 않는 오브젝트

향후 확장 가능성:

- 적 플레이어
- 특정 물리 오브젝트
- 별도 지정된 특수 오브젝트

### 앵커 상태

각 쿠나이는 다음과 같은 상태를 가집니다.

1. Ready: 발사 가능
2. Flying: 발사되어 비행 중
3. Anchored: 환경에 고정된 상태
4. Returning: 플레이어에게 회수되는 상태
5. Cooldown: 재사용 대기 상태

좌우 쿠나이는 서로 독립적으로 상태를 관리해야 합니다.

### 초기 밸런스 제안

| 항목 | 초기 설정 |
|---|---:|
| 최대 앵커 수 | 2개 |
| 앵커 최대 거리 | 35m |
| 앵커 유지 시간 | 20초 |
| 회수 후 재사용 | 회수 완료 후 가능 |
| 앵커 설치 방식 | 충돌 지점에 고정 |

수치는 확정값이 아니라 플레이 테스트를 위한 시작점입니다.

앵커의 최대 거리는 플레이어를 기준으로 계산합니다. 앵커가 최대 거리를 초과하거나 플레이어와의 연결이 불가능해지는 경우에는 정상적으로 회수 또는 만료 처리해야 합니다.

---

# 4. 모드 시스템

이 무기의 핵심은 두 가지 모드를 명시적으로 전환할 수 있다는 것입니다.

## 4-1. Mobility Mode

<목적>
앵커를 활용하여 플레이어가 빠르게 이동하고 전투 위치를 바꿀 수 있도록 합니다.

### 앵커가 0개인 경우
- E를 사용할 수 없습니다.
- 쿠나이를 발사하여 앵커를 설치해야 합니다.

### 앵커가 1개인 경우
- E를 누르면 해당 앵커 방향으로 플레이어가 끌려갑니다.
- 단순 순간이동이 아니라 물리적인 가속과 이동을 기반으로 구현합니다.
- 이동 중 플레이어가 방향을 조정할 수 있어야 합니다.

### 앵커가 2개인 경우
- E를 누르면 양쪽 앵커를 활용한 복합 기동을 실행합니다.
- 두 앵커의 위치를 기준으로 목표 이동 방향을 계산합니다.

기본 목표 지점:

P_target = (P_left + P_right) / 2

단, 이 지점을 향해 순간이동해서는 안 됩니다.

두 앵커의 위치를 활용하여 플레이어에게 가속도를 부여하고, 자연스러운 이동 궤적을 생성해야 합니다.

### 기동 중 조작

- WASD: 이동 방향 조정
- Space: 점프 및 이동 궤적 조정
- Slide: 기존 이동 관성을 활용한 슬라이딩
- 앵커 회수: 이동 경로 변경
- 새로운 쿠나이 발사: 새로운 이동 경로 확보

기동 중에도 플레이어의 조작권을 최대한 보장해야 합니다.

특히 이동이 자동으로 고정된 궤적을 따라가기만 하는 방식은 피합니다.

### 앵커 하나를 회수하는 경우

양쪽 앵커를 이용해 이동하던 중 한쪽을 회수하면 남아 있는 앵커를 중심으로 이동 방향을 변경할 수 있어야 합니다.

이를 활용하면:
- 장애물 주변을 돌아가는 기동
- 공중에서 방향을 변경하는 기동
- 적의 조준선을 벗어나는 회피
- 높은 지형으로 빠르게 이동

등의 플레이가 가능해야 합니다.

---

## 4-2. Thread Mode

<목적>
두 앵커 사이에 와이어를 설치하여 적의 이동을 감지하고 공간을 통제합니다.

### 와이어 설치 과정

1. 왼손 쿠나이를 발사하여 첫 번째 앵커를 설치합니다.
2. 오른손 쿠나이를 발사하여 두 번째 앵커를 설치합니다.
3. 두 앵커가 모두 유효한 위치에 설치되어 있는지 확인합니다.
4. E를 누르면 두 앵커 사이에 와이어를 설치합니다.

와이어는 두 앵커를 직접 연결하는 직선 형태로 시작합니다.

### 와이어 기능

적 플레이어가 와이어에 접근하거나 통과하면 다음 효과가 발생합니다.

- 와이어 설치자에게 적의 접근 또는 통과 사실을 알립니다.
- 적의 위치를 짧은 시간 동안 감지하거나 표시합니다.
- 적에게 짧은 이동 방해 효과를 적용할 수 있습니다.
- 와이어가 발동하면 시각적·청각적 피드백을 제공합니다.

### 와이어의 제약

- 와이어 자체는 강력한 직접 피해를 주지 않습니다.
- 적을 완전히 움직이지 못하게 만드는 강제 속박은 금지합니다.
- 와이어는 적이 발견하고 파괴할 수 있어야 합니다.
- 적에게도 와이어가 어느 정도 보이도록 하여 대응 기회를 제공합니다.
- 와이어는 설치자의 앵커가 유지되는 동안에만 정상적으로 작동합니다.

### 초기 밸런스 제안

| 항목 | 초기 설정 |
|---|---:|
| 와이어 유지 시간 | 8초 |
| 앵커 유지 시간 | 20초 |
| 설치 조건 | 유효한 앵커 2개 |
| 설치 방식 | 두 앵커 사이 직선 연결 |
| 적 감지 | 짧은 위치 표시 |
| 적 방해 | 짧은 이동 속도 감소 |
| 파괴 가능 여부 | 가능 |

**중요:** 앵커의 지속 시간과 와이어의 지속 시간은 서로 독립적으로 관리해야 합니다.

예를 들어 와이어가 8초 후 사라지더라도 앵커가 남아 있다면 플레이어는 해당 앵커를 이용해 기동할 수 있어야 합니다.

반대로 앵커가 만료되면 해당 앵커를 사용하는 와이어도 제거되어야 합니다.

---

# 5. 모드 전환 및 상태 유지

모드 전환은 자동으로 이루어지지 않습니다.

플레이어가 직접 Mobility Mode와 Thread Mode를 전환합니다.

### 모드 전환 규칙

- 모드 전환은 앵커의 상태를 변경하지 않습니다.
- 이미 설치된 앵커는 모드 전환 후에도 유지됩니다.
- 이미 설치된 와이어도 모드 전환만으로 제거되지 않습니다.
- 모드 전환은 E의 기능에만 영향을 줍니다.
- LMB와 RMB의 기능은 두 모드에서 동일합니다.

예시:

1. Mobility Mode에서 쿠나이 두 개를 설치합니다.
2. Thread Mode로 전환합니다.
3. E를 눌러 와이어를 설치합니다.
4. 다시 Mobility Mode로 전환합니다.
5. 기존 와이어는 유지되며, E를 누르면 앵커를 이용한 기동을 실행합니다.

이와 같은 방식으로 전투 중 상황에 맞게 기능을 전환할 수 있어야 합니다.

# 6. 기동 공격 시스템

이 무기는 이동 능력만 제공하는 것이 아니라 기동 자체를 공격 수단으로 활용할 수 있어야 합니다.

### Dash Collision Attack

Mobility Mode에서 앵커를 이용해 고속 이동하는 도중 적 플레이어와 충돌하면 공격이 발생합니다.

효과:

- 적에게 일정 피해를 줍니다.
- 짧은 넉백 또는 경직을 발생시킵니다.
- 충돌 후 해당 기동을 종료합니다.

### 구현 원칙

- 적을 자동으로 추적하는 유도 공격이 되어서는 안 됩니다.
- 플레이어의 실제 이동 경로와 충돌 판정을 기반으로 합니다.
- 한 번의 기동에서 동일한 적에게 반복적으로 피해가 들어가지 않도록 합니다.
- 공격 판정은 서버에서 검증해야 합니다.
- 기동의 속도와 충돌 방향에 따라 공격의 체감이 자연스러워야 합니다.

이 공격은 정면에서 적을 압도하기 위한 수단이 아니라, 기동을 성공적으로 활용했을 때 얻는 보상이어야 합니다.

---

# 7. 향후 확장 기능

초기 버전에서는 구현하지 않아도 되지만, 향후 확장을 고려하여 구조를 설계합니다.

### 7-1. 적에게 직접 쿠나이 명중

- 적에게 쿠나이를 직접 명중시키면 표식 부여
- 짧은 시간 위치 감지
- 약한 이동 방해
- 상황에 따라 짧은 방향성 끌어당김

단, 적을 장시간 무력화하거나 강제로 이동시키는 능력은 피합니다.

### 7-2. 다양한 와이어 구조

초기 버전에서는 직선 와이어 하나만 구현합니다.

향후 다음 형태를 고려할 수 있습니다.

- Cross Thread: 두 와이어가 교차하는 형태
- Vertical Thread: 수직 방향으로 설치하는 와이어
- Area Thread: 일정 구역을 감싸는 와이어
- Network Thread: 복수의 와이어를 연결한 네트워크

단, 쿠나이 두 개만으로 복수의 독립적인 영구 와이어를 무제한 생성할 수 있도록 설계하지 않습니다. 추가 앵커, 충전량 또는 별도 자원 시스템이 필요하다면 별도 기획합니다.

### 7-3. 오브젝트 상호작용

특정 오브젝트에 쿠나이를 설치하고 와이어를 활용해 끌어당기거나 이동시키는 기능을 고려할 수 있습니다.

초기에는 모든 물리 오브젝트를 대상으로 하지 않고, 명시적으로 상호작용이 허용된 오브젝트만 대상으로 합니다.

# 8. 전투 밸런스 방향

이 무기는 일반적인 총기와 다른 교전 구조를 가져야 합니다.

| 교전 거리 | 역할 |
|---|---|
| 근거리 | 쿠나이 직접 명중, 기동 충돌 공격 |
| 중거리 | 앵커 설치, 와이어 연결, 기동 경로 확보 |
| 장거리 | 적 위치 감지, 이동 경로 구축, 전장 정보 확보 |

### 강점
- 빠른 기동
- 예상하기 어려운 진입 경로
- 적의 이동 경로 통제
- 와이어를 통한 정보 확보
- 높은 숙련도에 따른 다양한 플레이

### 약점
- 정면 화력 부족
- 앵커 설치를 위한 준비 필요
- 설치 위치에 따른 기동 제약
- 와이어 파괴 가능
- 능력을 잘못 사용하면 이동 경로가 노출될 수 있음

이 무기는 돌격소총이나 저격총을 대체하는 무기가 아닙니다. 다른 무기로는 만들기 어려운 이동 경로와 전술적 선택지를 제공하는 것이 목적입니다.

---

# 9. HUD 및 시각적 피드백

플레이어가 복잡한 상태를 쉽게 이해할 수 있도록 HUD를 구성합니다.

### 표시 요소

- 현재 모드: Mobility / Thread
- 왼손 쿠나이 상태
- 오른손 쿠나이 상태
- 각 앵커의 남은 지속 시간
- 와이어 설치 가능 여부
- 설치된 와이어의 남은 지속 시간
- 현재 E 능력의 기능

### 시각적 피드백

쿠나이 발사:
- 손에서 쿠나이가 발사되는 애니메이션
- 쿠나이 비행 궤적
- 충돌 시 작은 파티클 및 사운드

앵커 설치:
- 앵커가 표면에 고정되는 시각 효과
- 손목과 앵커를 연결하는 와이어 렌더링
- 앵커 상태를 확인할 수 있는 UI

와이어 설치:
- 두 앵커 사이에 와이어가 생성되는 애니메이션
- 와이어가 활성화되었음을 보여주는 시각적 효과
- 적에게도 와이어를 발견할 수 있는 적절한 표현

와이어 발동:
- 발동 시 짧은 시각 효과
- 설치자에게 전달되는 UI 알림
- 적에게 적용되는 효과의 피드백

기동:
- 와이어가 팽팽해지는 표현
- 가속에 따른 카메라 피드백
- 자연스러운 이동 애니메이션

시각 효과는 게임 화면을 지나치게 가리거나 경쟁전에서 시야를 방해하지 않도록 절제합니다.

# 10. 멀티플레이어 및 네트워크 구조

이 게임은 멀티플레이어 FPS이므로 서버 권한을 반드시 고려해야 합니다.

### 서버에서 처리할 사항

- 쿠나이 발사 및 유효성 검증
- 앵커 설치 위치
- 앵커의 상태와 지속 시간
- 와이어 설치 및 제거
- 와이어 충돌 및 적 감지
- 피해 및 넉백 판정
- 기동 공격의 적중 판정
- 플레이어의 이동 및 기동 상태 검증

### 클라이언트에서 처리할 사항

- 쿠나이 및 와이어 렌더링
- 발사 및 회수 애니메이션
- 와이어의 시각적 표현
- 사운드 및 파티클
- HUD 업데이트
- 입력 반응 및 예측 가능한 시각 효과

클라이언트에서만 적중 여부나 와이어 발동 여부를 결정해서는 안 됩니다.

서버가 최종적인 게임 판정을 담당해야 합니다.

특히 와이어가 적을 감지하는 판정과 기동 중 적과 충돌하는 판정은 서버에서 검증해야 합니다.

네트워크 지연으로 인해 와이어나 앵커가 순간이동하거나 부자연스럽게 끊기는 현상이 발생하지 않도록 주의합니다.

# 11. 기존 게임 시스템과의 통합

기존 게임의 시스템을 우선적으로 재사용합니다.

- 기존 무기 등록 및 장착 시스템
- 기존 좌우 마우스 입력 처리
- 기존 무기 능력 시스템
- 기존 이동 및 슬라이딩 시스템
- 기존 서버 권한 기반 전투 판정
- 기존 플레이어 애니메이션 시스템
- 기존 HUD 및 무기 UI
- 기존 1인칭 및 3인칭 렌더링 구조

새로운 무기를 추가하기 위해 기존 무기 시스템 전체를 재작성하지 않습니다.

또한 기존 무기의 발사, 재장전, 교체, 능력 사용 등에 영향을 주지 않아야 합니다.

### 이동 시스템과의 호환성

기존 게임의 이동 규칙을 유지해야 합니다.

- 모든 무기에서 슬라이딩 가능
- 조준 중에는 달리기 불가능
- 무기 종류에 따른 달리면서 사격 가능 여부 유지
- 기존 점프 및 이동 판정 유지

Dual Kunai는 별도의 기동 능력을 추가하는 것이며, 기존 이동 시스템을 무시하거나 우회하는 방식으로 구현해서는 안 됩니다.

# 12. 개발 단계 및 구현 순서

모든 기능을 한 번에 구현하지 않습니다.

각 단계가 독립적으로 작동하는 상태를 만든 다음 다음 단계로 넘어갑니다.

### W1. Dual Kunai 기본 시스템
- 좌우 쿠나이 개별 발사
- 쿠나이 비행
- 환경 충돌
- 앵커 설치
- 앵커 회수
- 좌우 독립 상태 관리

### W2. Mobility Mode
- 단일 앵커 기동
- 양쪽 앵커 복합 기동
- 이동 방향 조정
- 점프 및 슬라이딩 연동
- 앵커 회수에 따른 이동 경로 변경

### W3. Mode Switching
- Mobility / Thread 모드 전환
- E 능력 분기
- 모드 전환 시 앵커 상태 유지
- HUD 연동

### W4. Thread System
- 두 앵커 사이 와이어 생성
- 와이어 충돌 판정
- 적 감지
- 짧은 이동 방해 효과
- 와이어 파괴

### W5. Lifetime & Recall
- 앵커 20초 지속 시간
- 와이어 8초 지속 시간
- 독립적인 지속 시간 관리
- 만료 및 회수 처리
- 앵커 만료 시 연결된 와이어 제거

### W6. Dash Collision Attack
- 기동 중 적과 충돌 감지
- 피해
- 넉백 또는 짧은 경직
- 기동 종료
- 중복 적중 방지

### W7. 고급 기능
- 적에게 쿠나이 직접 명중
- 적 표식 및 감지
- 오브젝트 상호작용
- 다양한 와이어 형태

초기 출시 목표는 **W1~W6**입니다. W7 이후 기능은 초기 무기가 정상적으로 작동하고 밸런스가 확인된 후 진행합니다.

# 13. 개발 시 반드시 지켜야 할 원칙

1. 기존 프로젝트의 구조와 코딩 규칙을 우선합니다.
2. 기존 무기 시스템을 불필요하게 재작성하지 않습니다.
3. 서버 권한 기반 판정을 유지합니다.
4. 좌우 쿠나이의 상태는 독립적으로 관리합니다.
5. 앵커와 와이어의 지속 시간은 분리합니다.
6. 모드 전환으로 기존 앵커나 와이어가 사라지면 안 됩니다.
7. 순간이동이 아닌 물리적 기동을 구현합니다.
8. 기존 이동 및 슬라이딩 시스템과 호환되어야 합니다.
9. 1인칭과 3인칭 모두에서 자연스럽게 보이도록 합니다.
10. 실제 플레이에서 반응성이 좋고 조작이 직관적이어야 합니다.
11. 초기 버전에서 필요하지 않은 확장 기능을 미리 구현하지 않습니다.
12. 불필요한 전체 코드 분석, 중복 검사, 과도한 테스트를 피하고 현재 단계에 필요한 작업만 진행합니다.

# 14. 최종 목표

Dual Kunai는 단순히 적에게 피해를 주는 무기가 아닙니다.

플레이어가 전장에 앵커를 설치하고, 와이어를 연결하고, 적의 움직임을 읽고, 그 구조를 이용해 예상하지 못한 방향에서 진입하는 무기입니다.

숙련된 플레이어는 앵커와 와이어를 활용해 전투 공간 자체를 자신의 플레이 영역으로 바꿀 수 있어야 합니다.

최종적으로 다음 세 가지가 모두 성립해야 합니다.

- 기동 능력만으로도 독특한 플레이가 가능할 것
- 와이어 설치와 공간 통제만으로도 전술적 가치가 있을 것
- 두 기능을 조합하면 더욱 강력하고 창의적인 플레이가 가능할 것

이 세 가지가 유기적으로 결합된 고유한 특수 무기를 구현합니다.
